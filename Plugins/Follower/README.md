# Follower

GameHelper 原生跟随插件：扫描玩家名字，按地形路线跟随。支持原有小号端 WASD 模式，以及本地双人“共享 WASD 追队长、方向箭头让 P2 靠拢 P1”模式。两种模式都要求游戏保持前台。当前是可编译、通过离线检查的原型；此前仅独立探针的前台 W 获得用户确认，完整跟随与新增箭头输入仍需实机验证。

## 本地双人：共同跟随与 P2 纠偏

1. 用户自行保留现有虚拟手柄映射：**↑ ↓ ← → 只控制 P2**。插件不安装、配置虚拟手柄，也不会改变游戏的 WASD 绑定。
2. 编译并运行当前源码，在 Follower 设置中勾选 **“本地双人：共享 WASD + P2 方向键纠偏”**。切换模式会停止旧输入，并重新开启“只预览路线”。
3. 分别从 **队长、P1、P2** 三个下拉名单选择角色。名单包含当前角色和附近可见玩家，选中立即保存；不假设核心当前角色是哪一方，不用 Radar 的“第一个其他玩家”推断 P2。P2 必须不同于 P1 和队长；名字不唯一或找不到队长时退出跟随，P1/P2 暂时不可见则等待自动恢复。P1 也可以选为队长，此时共同跟随阶段不移动，只在两人分离时纠偏。
4. 关闭设置、回到游戏，尚未开启时按启停快捷键（默认 F6），检查状态中的当前阶段、角色、P1/P2 间距、拟发送按键和路线。正常路线为 **P1 → 队长**；纠偏路线为 **P2 → P1**。使用相应角色的实际位置和高度，不使用两人中点，也不记录或回放足迹。
5. 确认角色和路线后，取消“只预览路线”。如果跟随已经开启，关闭设置并回到游戏会自动开始实际移动，无需再按启停键；如果状态为“已停止”，再按启停键开始。Esc 或启停快捷键主动停止后不会自动重启。

阶段规则如下，所有距离均为地形网格单位：

| 阶段 | 寻路与输入 | 切换条件 |
| --- | --- | --- |
| 共同跟随 | 根据 P1 → 队长的路线发送 WASD，用户的绑定使两人一起移动 | P1/P2 间距达到默认 **35** 时进入纠偏 |
| P2 纠偏 | 先松开 WASD、暂停 P1，再按 P2 → P1 的路线发送箭头 | 两人间距缩小到默认 **12** 以内且中间可直达时，松开箭头、恢复共同跟随 |

纠偏只处理 P1/P2 的间距，不检查 P2 是否追到队长，也不要求 P2 必须落在 P1 后方。触发/恢复间距可在设置中调整，两档间距用于避免频繁切换。即使队长还很远，P2 靠拢 P1 后也会结束纠偏。共同跟随仍使用原来的队长停止/恢复距离（默认 18/25）；P1 已在队长附近时恢复共同跟随会保持停止。

插件不会同时保持 WASD 和方向箭头；切换阶段时释放旧键、取消旧路线，再为另一名角色计算路线。额外的手动 WASD 或方向箭头会使插件松键等待，手动按键松开后自动恢复；插件已按住的同一个键无法与物理按键可靠区分，需要持续接管时请用 Esc 或启停快捷键。纠偏中失焦、开面板或短暂手动操作会保留纠偏阶段，回来后继续以 P1 为目标；切图或角色身份变化时重新定位。

方向箭头采用扩展扫描码，按下、释放均设置扩展键标志，区别于数字小键盘；实现依据 [Microsoft KEYBDINPUT 文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-keybdinput)。虚拟手柄软件是否接受 `SendInput` 合成事件尚未验证，物理箭头能控制 P2 不等于合成箭头一定可用。

允许此模式在手柄界面运行。当前核心在手柄模式下将 `ChatParent` 清零，因此不再仅因该指针为空就拒绝运行；**手柄聊天状态目前不可观测，打开聊天前请先用 Esc 或启停键主动停止跟随**。仅按 Enter 只能在按住期间阻止输入，不能代替主动停止。已识别的大面板、设置、失焦、死亡、角色身份变化和切区会松键等待，条件恢复后自动继续。手柄面板识别依赖现有核心，尚未进行双人界面实测。

旧配置缺少新字段时仍使用原 WASD 模式。`LocalCoopFollow`、`P1Name`、`P2Name`、`P2LagDistance`、`P2RejoinDistance` 独立保存，原 `LeaderName` 继续表示最终队长，关闭双人选项即可返回原模式。

## 原有 WASD 模式

1. 在仓库根目录执行 `dotnet build GameOverlay.sln -c Release`，使用该构建目录的 GameHelper。插件自动复制到 `GameHelper/bin/Release/net10.0-windows/win-x64/Plugins/Follower/`。
2. 在小号游戏中选择 **WASD 移动**。GameHelper 必须连接小号进程。
3. F12 启用 Follower，打开“选择附近玩家”，从扫描出的名字中选队长。排除小号自己，名字去重并排序；选中后立即保存，不需要手动输入。没有候选时，让两人进入同一区域并靠近后再展开列表。
4. 在“开始/停止快捷键”下拉框选择按键，选中立即保存，重启保留。默认 **F6**，避免与游戏 F8 截图冲突；旧配置没有该项时也使用 F6。WASD、四个方向箭头、Esc、Enter 和修饰键不参与选择；旧配置若把方向箭头用作启停键，会恢复为 F6。
5. 默认勾选“只预览路线”。关闭设置、回到游戏，按所选快捷键查看路线、距离和拟发送的按键。
6. 确认定位和路线后，在设置里取消“只预览路线”。已经开启跟随时，关闭设置并回到游戏会自动实际移动；已停止时才需要按所选快捷键启动。**所选快捷键切换启停，Esc 停止**。菜单和状态提示随选择显示实际按键。

默认停止距离 18、重新跟随距离 25，单位为游戏地形网格；间隔用于避免在距离边缘反复启停。期望离墙间距默认 1：有空间时优先离墙，贴墙起步、目标贴墙和窄道不会再仅因间距不足判定无路；0 表示不额外偏好离墙，真实障碍仍不可穿过。旧配置的 `Clearance` 数值保留，改为路线偏好。配置保存在插件的 `config/settings.txt`，重启保留选中的名字与参数，但不会自动开始移动。

## 自动等待与脱困

跟随开关与是否正在按键分开：临时不能移动时松键，但保持跟随开启。通常每 250 毫秒重新检查，输入失败每 500 毫秒、异常每 1 秒重试。

| 情况 | 行为 |
| --- | --- |
| 游戏失焦、聊天/面板/设置打开、Enter 或修饰键按住、额外手动移动 | 松键等待，条件恢复后自动重新寻路 |
| 绘制暂停或延迟、切图、游戏状态变化、角色身份变化、地形/坐标暂时不可用、距离超过 600 格 | 释放旧输入和路线，等待可用数据后自动继续 |
| P1/P2 暂时不可见、死亡或组件不可读；队长名字仍可见但死亡或组件不可读 | 等待角色恢复，不撤销开启状态 |
| 找不到所选队长，或名字未选/同名歧义/角色选择冲突 | 退出跟随，解决后需要按启停键重新开始 |
| 用户按启停键/Esc，或禁用插件 | 主动停止，后续恢复事件不会自动开启 |

需要移动但默认 **2.5 秒**没有至少 2 格位移时，自动进入脱困。一直无路线、等待寻路或没有可行方向也计入无进展时间。设置项改为“无进展多久后尝试脱困”，沿用原 `StuckMilliseconds` 数值；仅预览时不发送按键，也不执行脱困。

脱困直接朝当前目标强制短按，**不再用地形、墙角或门阻挡判断过滤方向，也不轮流试侧向/后退**。普通跟随的 A* 和绕障逻辑保留，但它们无路或拒绝发键时，脱困仍会按受控角色到当前目标的方向尝试，依靠游戏里的真实碰撞与位移反馈。目标换方向时先松开旧键，再朝新方向尝试；没有有效坐标/投影时无法确定方向，状态会明确显示等待。

每次短按约 **150 毫秒**，松键观察 **120 毫秒**，每轮最多八次短按；产生至少 1 格实际位移便立即结束试探、重算路线。整轮无进展则休息 1 秒、重新寻路，仍卡住时再进行下一轮，不因失败次数退出跟随。强制发键不代表角色一定走得通，也不会自动开门。游戏前台、有效角色/区域、预览、面板、手动接管和停止保护仍然生效；地形数据完全缺失/坐标越界与 600 格范围限制仍先等待。

**共同跟随阶段按 P1 → 队长方向发送 WASD 脱困；P2 纠偏阶段按 P2 → P1 方向仅发箭头脱困。** 两组输入仍互斥；纠偏结束条件保持 P1/P2 距离和直达条件。

## 行为与边界

- 从原有 `AwakeEntities`、`Player.Name`、`Render.GridPosition` 读取目标。当前没有使用经过验证的队伍成员列表，候选是**附近可见玩家**，不保证每个候选都在队伍中；由用户选择目标，不自动选择陌生人或最近玩家。
- 读取原有 `GridWalkableData` / `TerrainMetadata.BytesPerRow`。沿用 Radar 的半字节地形解码与八方向 A* 思路，在插件内实现坐标边界、禁止斜穿墙角、节点/耗时预算，以及可取消的后台寻路。离墙间距通过路径代价体现，不把墙边可走格变成障碍；路线前瞻也比较这一代价，避免直线捷径把离墙路线重新拉回墙边。普通导航的停止距离和按键方向仍检查地形，强制脱困不使用阻挡过滤。无需启用或依赖 Radar DLL。
- Radar 不扩大墙体，并允许在半径 75 格内为阻挡的起终点寻找替代格；还会简化显示路线。Follower 不做可能跨墙的起终点替换：如果坐标所在格在原始地形中被标为阻挡，普通寻路会失败，但强制脱困仍会发出朝目标方向的短按。搜索上限也不同：Radar 默认 100 万次迭代、直线距离 2500 格；Follower 保留 4 万次出队/约 100 毫秒预算、600 格距离限制。因此雷达能画线并不保证当前跟随能走通。
- Radar 的 `BuildDoorOverrideMap` 会无条件把门附近设为可通行。Follower 只为已知 `TriggerableBlockage.IsBlocked == false` 的门提供通行修正；关闭或无法确认状态的门当作障碍。门的组件状态与修正范围仍需实机验证。**不会点击开门、使用传送门或自动跨区。**
- 通过原有 `WorldToScreen` 计算受控角色当前位置的投影方向，将下一段路线转换成当前模式的 WASD 或方向箭头/斜向组合，并检查该方向的短距离地形。强制脱困直接投影当前目标方向，不使用路线或地形过滤。路线预览按受控角色当前高度绘制，坡道上可能与地面不完全贴合；真实键盘方向、走速、碰撞和窄道表现待实测。
- 仅使用标准 Windows `SendInput` 扫描码；调用前核对前台窗口 PID。当前客户端已由用户确认前台 W 单键测试能移动，其他环境仍需验证；此 API 受 Windows 完整性级别限制，参考 [Microsoft SendInput 文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)。不提供后台双开输入。
- 临时中断与真正停止的区别见上表。客户端看不到队长时，没有远距离坐标可用，会退出跟随，不追逐旧坐标。切图本身只等待；新区域就绪后仍找不到队长，则按目标丢失处理。
- 不持久化运行状态。独立 25 毫秒定时器检查按键租期：没有有效绘制帧续期 200 毫秒后释放普通移动键；脱困短按只续到本次试探结束时间。因此 F9 暂停绘制或主循环卡顿不会一直保持移动键。重新绘制时超过 300 毫秒间隔会清掉旧路线并短暂等待，稳定后自动继续；定时器会记住游戏前台时按下的 Esc，即使暂停绘制期间按下又松开也不会被自动恢复覆盖。切换映射前按原扫描码释放旧键；释放失败时保留原映射并由定时器重试。正常禁用和进程退出也释放已发送的键。操作系统强制终止进程不执行清理回调。
- 原模式检测额外手动 WASD；双人模式检测额外手动 WASD 和方向箭头。Ctrl/Alt/Windows 键也会使插件松键等待，松开后自动恢复。无法区分用户是否物理按住了插件已经按下的同一个键，需要持续手动接管时请用 Esc 或启停快捷键。

本次**没有修改 GameHelper 核心、GameOffsets 或 Radar**，复用当前仓库已有公开接口；没有重新验证此插件与其他历史或原版核心的二进制兼容性。

Follower 离线检查覆盖障碍绕行、贴墙起终点、窄道和拐弯、离墙偏好与前瞻、门覆盖、边界、墙角、寻路取消/预算、投影方向、按键释放/发送失败、跟随距离和卡住检测。双人检查覆盖队长/P1/P2 显式选择、核心当前角色可为任意一方、重复实体/同名歧义/角色缺失、35/12 间距切换、靠拢即可结束纠偏、阶段切换后的进展与距离状态、箭头扩展扫描码、混合手动输入识别、映射切换前释放和失败重试、旧设置默认值。自动恢复检查覆盖临时等待重试、目标丢失/配置错误退出、主动停止不可被事件重启、无路线超时、短按与休息、全阻挡地形仍朝目标发键、目标换向先释放、位移后重算、短租期过期和两阶段输入互斥；不会连接游戏或发送真实按键。插件加载检查调用真实 `PManager`，包括 Follower，但不调用 `OnEnable`，不等于实机测试。
