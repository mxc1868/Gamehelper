# Follower

GameHelper 原生跟随插件：扫描玩家名字，按地形路线跟随。支持原有小号端 WASD 模式，以及本地双人“共享 WASD 追队长、方向箭头让 P2 靠拢 P1”模式。两种模式都要求游戏保持前台。当前是可编译、通过离线检查的原型；此前仅独立探针的前台 W 获得用户确认，完整跟随与新增箭头输入仍需实机验证。

## 本地双人：共同跟随与 P2 纠偏

1. 用户自行保留现有虚拟手柄映射：**↑ ↓ ← → 只控制 P2**。插件不安装、配置虚拟手柄，也不会改变游戏的 WASD 绑定。
2. 编译并运行当前源码，在 Follower 设置中勾选 **“本地双人：共享 WASD + P2 方向键纠偏”**。切换模式会停止旧输入，并重新开启“只预览路线”。
3. 分别从 **队长、P1、P2** 三个下拉名单选择角色。名单包含当前角色和附近可见玩家，选中立即保存；不假设核心当前角色是哪一方，不用 Radar 的“第一个其他玩家”推断 P2。P2 必须不同于 P1 和队长；名字不唯一或任一角色不可见时停止。P1 也可以选为队长，此时共同跟随阶段不移动，只在两人分离时纠偏。
4. 关闭设置、回到游戏，按启停快捷键（默认 F6）检查状态中的当前阶段、角色、P1/P2 间距、拟发送按键和路线。正常路线为 **P1 → 队长**；纠偏路线为 **P2 → P1**。使用相应角色的实际位置和高度，不使用两人中点，也不记录或回放足迹。
5. 确认角色和路线后，取消“只预览路线”，回到游戏按启停快捷键。Esc 或启停快捷键停止。

阶段规则如下，所有距离均为地形网格单位：

| 阶段 | 寻路与输入 | 切换条件 |
| --- | --- | --- |
| 共同跟随 | 根据 P1 → 队长的路线发送 WASD，用户的绑定使两人一起移动 | P1/P2 间距达到默认 **35** 时进入纠偏 |
| P2 纠偏 | 先松开 WASD、暂停 P1，再按 P2 → P1 的路线发送箭头 | 两人间距缩小到默认 **12** 以内且中间可直达时，松开箭头、恢复共同跟随 |

纠偏只处理 P1/P2 的间距，不检查 P2 是否追到队长，也不要求 P2 必须落在 P1 后方。触发/恢复间距可在设置中调整，两档间距用于避免频繁切换。即使队长还很远，P2 靠拢 P1 后也会结束纠偏。共同跟随仍使用原来的队长停止/恢复距离（默认 18/25）；P1 已在队长附近时恢复共同跟随会保持停止。

插件不会同时保持 WASD 和方向箭头；切换阶段时释放旧键、取消旧路线，再为另一名角色计算路线。额外的手动 WASD 或方向箭头都会停止双人跟随，避免与当前阶段混用；插件已按住的同一个键无法与物理按键可靠区分，接管请用 Esc 或启停快捷键。

方向箭头采用扩展扫描码，按下、释放均设置扩展键标志，区别于数字小键盘；实现依据 [Microsoft KEYBDINPUT 文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-keybdinput)。虚拟手柄软件是否接受 `SendInput` 合成事件尚未验证，物理箭头能控制 P2 不等于合成箭头一定可用。

允许此模式在手柄界面运行。当前核心在手柄模式下将 `ChatParent` 清零，因此不再仅因该指针为空就拒绝运行；**手柄聊天状态目前不可观测，打开聊天前请先停止跟随**。Enter、Esc、已识别的大面板、设置、失焦、死亡、角色身份变化和切区仍会停止或阻止输入。手柄面板识别依赖现有核心，尚未进行双人界面实测。

旧配置缺少新字段时仍使用原 WASD 模式。`LocalCoopFollow`、`P1Name`、`P2Name`、`P2LagDistance`、`P2RejoinDistance` 独立保存，原 `LeaderName` 继续表示最终队长，关闭双人选项即可返回原模式。

## 原有 WASD 模式

1. 在仓库根目录执行 `dotnet build GameOverlay.sln -c Release`，使用该构建目录的 GameHelper。插件自动复制到 `GameHelper/bin/Release/net10.0-windows/win-x64/Plugins/Follower/`。
2. 在小号游戏中选择 **WASD 移动**。GameHelper 必须连接小号进程。
3. F12 启用 Follower，打开“选择附近玩家”，从扫描出的名字中选队长。排除小号自己，名字去重并排序；选中后立即保存，不需要手动输入。没有候选时，让两人进入同一区域并靠近后再展开列表。
4. 在“开始/停止快捷键”下拉框选择按键，选中立即保存，重启保留。默认 **F6**，避免与游戏 F8 截图冲突；旧配置没有该项时也使用 F6。WASD、四个方向箭头、Esc、Enter 和修饰键不参与选择；旧配置若把方向箭头用作启停键，会恢复为 F6。
5. 默认勾选“只预览路线”。关闭设置、回到游戏，按所选快捷键查看路线、距离和拟发送的按键。
6. 确认定位和路线后，在设置里取消“只预览路线”，回到游戏再按所选快捷键开始移动。**所选快捷键切换启停，Esc 停止**。菜单和状态提示随选择显示实际按键。

默认停止距离 18、重新跟随距离 25，单位为游戏地形网格；间隔用于避免在距离边缘反复启停。期望离墙间距默认 1：有空间时优先离墙，贴墙起步、目标贴墙和窄道不会再仅因间距不足判定无路；0 表示不额外偏好离墙，真实障碍仍不可穿过。旧配置的 `Clearance` 数值保留，改为路线偏好。配置保存在插件的 `config/settings.txt`，重启保留选中的名字与参数，但不会自动开始移动。

## 行为与边界

- 从原有 `AwakeEntities`、`Player.Name`、`Render.GridPosition` 读取目标。当前没有使用经过验证的队伍成员列表，候选是**附近可见玩家**，不保证每个候选都在队伍中；由用户选择目标，不自动选择陌生人或最近玩家。
- 读取原有 `GridWalkableData` / `TerrainMetadata.BytesPerRow`。沿用 Radar 的半字节地形解码与八方向 A* 思路，在插件内实现坐标边界、禁止斜穿墙角、节点/耗时预算，以及可取消的后台寻路。离墙间距通过路径代价体现，不把墙边可走格变成障碍；路线前瞻也比较这一代价，避免直线捷径把离墙路线重新拉回墙边。停止距离和实际按键方向检查使用真实障碍。无需启用或依赖 Radar DLL。
- Radar 不扩大墙体，并允许在半径 75 格内为阻挡的起终点寻找替代格；还会简化显示路线。Follower 不做可能跨墙的起终点替换：如果坐标所在格在原始地形中确实阻挡，仍会停止。搜索上限也不同：Radar 默认 100 万次迭代、直线距离 2500 格；Follower 保留 4 万次出队/约 100 毫秒预算、600 格距离限制。因此雷达能画线并不保证当前 WASD 跟随能走通。
- Radar 的 `BuildDoorOverrideMap` 会无条件把门附近设为可通行。Follower 只为已知 `TriggerableBlockage.IsBlocked == false` 的门提供通行修正；关闭或无法确认状态的门当作障碍。门的组件状态与修正范围仍需实机验证。**不会点击开门、使用传送门或自动跨区。**
- 通过原有 `WorldToScreen` 计算受控角色当前位置的投影方向，将下一段路线转换成当前模式的 WASD 或方向箭头/斜向组合，并检查该方向的短距离地形。路线预览按受控角色当前高度绘制，坡道上可能与地面不完全贴合；真实键盘方向、走速、碰撞和窄道表现待实测。
- 仅使用标准 Windows `SendInput` 扫描码；调用前核对前台窗口 PID。当前客户端已由用户确认前台 W 单键测试能移动，其他环境仍需验证；此 API 受 Windows 完整性级别限制，参考 [Microsoft SendInput 文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)。不提供后台双开输入。
- 死亡、目标或受控角色不可见/身份变化、切区、游戏失焦、已识别的聊天或大面板打开、设置打开、异常均停止；恢复后需要按启停快捷键。手柄聊天的识别限制见上。卡住约 2.5 秒停止，默认不反复撞墙。客户端看不到队长时，没有远距离坐标可用，也不会追逐旧坐标。
- 不持久化运行状态。独立 25 毫秒定时器检查按键租期：没有有效绘制帧续期 200 毫秒后释放按键，因此 F9 暂停绘制或主循环卡顿不会一直保持移动键；重新绘制时超过 300 毫秒间隔会停止跟随。切换映射前按原扫描码释放旧键；释放失败时保留原映射并由定时器重试。正常禁用和进程退出也释放已发送的键。操作系统强制终止进程不执行清理回调。
- 原模式检测额外手动 WASD；双人模式检测额外手动 WASD 和方向箭头。Ctrl/Alt/Windows 键也会停止。无法区分用户是否物理按住了插件已经按下的同一个键，手动接管请用 Esc 或启停快捷键。

本次**没有修改 GameHelper 核心、GameOffsets 或 Radar**，复用当前仓库已有公开接口；没有重新验证此插件与其他历史或原版核心的二进制兼容性。

## 检查与来源

```powershell
dotnet run --project tests/Follower.Tests/Follower.Tests.csproj -c Release
dotnet run --project tests/PluginLoad.Tests/PluginLoad.Tests.csproj -c Release -- GameHelper/bin/Release/net10.0-windows/win-x64
```

Follower 离线检查覆盖障碍绕行、贴墙起终点、窄道和拐弯、离墙偏好与前瞻、门覆盖、边界、墙角、寻路取消/预算、投影方向、按键释放/发送失败、跟随距离和卡住检测。新增检查覆盖队长/P1/P2 显式选择、核心当前角色可为任意一方、重复实体/同名歧义/角色缺失、35/12 间距切换、靠拢即可结束纠偏、阶段切换后的进展与距离状态、箭头扩展扫描码、混合手动输入停止、映射切换前释放和失败重试、旧设置默认值；不会连接游戏或发送真实按键。插件加载检查调用真实 `PManager`，包括 Follower，但不调用 `OnEnable`，不等于实机测试。

2026-09-25 本地实测：独立探针用与插件相同的 `SendInput` W 扫描码按住约半秒再松开，系统按键状态恢复，全程游戏前台，用户确认角色移动。此前通过 `PostMessage` 发送窗口按下/松开消息，后台与前台对照均未观察到移动，虽然 Windows 返回投递成功。因此保留前台 SendInput，不把窗口消息方式列为可用的后台输入方案。完整跟随、A/S/D 与斜向移动、地形避障和失焦清理仍需游戏内验证。
